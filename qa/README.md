# QA — тест-планы BlockDuel 9×9

Полномасштабные матрицы ручных проверок. Файлы **генерируются**, вручную не
редактируются.

## Сквозные каталоги сценариев (правило «1000 и 1»)

| Файл | Охват | Пунктов |
|------|-------|---------|
| `SCENARIOS_APP.md` | Всё приложение, платформо-независимо | **ровно 1001** |
| `SCENARIOS_MODE_<id>.md` | Каждый режим отдельно (13 файлов) | **ровно 1001** каждый |

**Ось «всё приложение»** (`SCENARIOS_APP.md`): 1001 сквозной сценарий (область ×
функция × состояние), ID `APP-0001…APP-1001`. Образец: `test/scenarios/app_scenarios_test.dart`.

**Ось «режим»** (`SCENARIOS_MODE_<id>.md`, id из реестра `lib/modes/game_mode_descriptor.dart`:
bot, hotseat, arcade, botvbot, online, memorySolo, memoryDuel, coop, match3,
tetris, puzzle, showcase, tutorial): по 1001 на режим, ID `MODE-<ID>-0001…-1001`.
Разделы: жизненный цикл, рендер×темы, ввод, **механика режима** (уникальная
логика), прогрессия, настройки, ошибки. Хвост «Property-фаззинг» (seed × конфиг ×
инвариант) добирает до 1001 в режимах малой игровой поверхности — это valid
property-тесты (фаззинг детерминированного ядра), не филлер; крупные режимы
(bot/online/tetris/puzzle) закрыты почти целиком механикой. Образец:
`test/scenarios/mode_scenarios_test.dart`.

Общее: устойчивые ID между прогонами, каждый ~7-й помечен `[C]` (smoke), гибрид
«генератор + образец». Регенерация всех каталогов: `python3 tools/gen_scenarios.py`.

Планируемая следующая ось (по запросу): `SCENARIOS_CODE_<platform>.md` (1001 на
код/платформу) — тот же механизм `exactly_n()`/`fuzz_matrix()` в генераторе.

## Как устроено

Матрица собирается из измерений предметной области (экраны × темы × состояния;
фигуры × ориентации × постановка; режимы × правила; онлайн-флоу × сетевые
условия; протокол; магазин; **реальные 120 достижений × 12 фасетов**; настройки;
звук; хранение/sync/auth; локализация; производительность; ошибки) плюс
платформо-специфичные разделы.

Достижения подтягиваются из `lib/achievements/definitions.dart` — при
изменении каталога перегенерируй планы.

## Регенерация

```bash
python3 tools/gen_test_plan.py
```

Перезаписывает 4 файла в `qa/`. Генератор детерминированный (одинаковый ввод →
одинаковый вывод), поэтому диффы читаемы.

## Как пользоваться

- **Smoke (каждая сборка):** прогоняй только пункты с маркером `[C]` —
  критический срез (~14% матрицы).
- **Полный регресс (перед релизом/cut-over):** весь файл платформы.
- Чекбоксы `- [ ]` отмечай прямо в копии файла под конкретный прогон/билд.

## Связанное

- Автотесты (Vitest/Flutter `flutter test`) покрывают ядро/нотифайеры/виджеты —
  это нижний слой; ручные планы покрывают то, что автотест не ловит (рендер,
  платформенная интеграция, ввод, звук, сеть в реальных условиях).
- Парность интерфейса с TS — `INTERFACE_PARITY.md` в корне.
