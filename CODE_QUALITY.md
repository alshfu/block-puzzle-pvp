## Планка «чистого кода» в этом проекте

«Чисто» здесь означает не «ноль строк в отчёте IDE по всему репозиторию»
(это недостижимо и не нужно), а вот что:

1. **Живой код** (`lib/`, `server/`, `web/`, `legacy-ts/core`, `tools/`) — без
   реальных проблем.
2. **Гейты качества зелёные:**
   - `flutter analyze` → **No issues found** ✅
   - `flutter test` (≈398) + `npm test` (96) → зелёные ✅
   - `npm run typecheck` → чисто ✅
   - CI (`.github/workflows/deploy.yml`) гоняет analyze+test на каждый push.
3. **Замороженный код** (`legacy/`, `legacy-ts/ui/`, `party/`) — исключён из
   инспекций, потому что его **нельзя развивать** (правило из `CLAUDE.md`).
4. **Ложные срабатывания** — осознаны и задокументированы (ниже), а не «замолчаны».

Это профессиональная планка. У любого большого проекта (включая сам Flutter)
инспекции IDE выдают тысячи подсказок — это фоновый шум инструмента, а не оценка
качества. Настоящий инженер **настраивает инструмент показывать правду**, а не
гоняется за нулём в артефактах и чужом замороженном коде.

## Что сделано (2026-08-26)

- **`web/index.html`** — добавлен `lang="ru"` в `<html>` (реальная a11y-правка
  для шиппинг-кода).
- **`tools/pentest_local.mjs`** — промис `main()` теперь обрабатывается через
  `.catch` (осмысленный код выхода при падении).
- **`.idea/block_puzzle_pvp.iml`** — из инспекций исключены `legacy/`,
  `legacy-ts/ui/`, `party/` (это `.idea/`, он в `.gitignore` → правка локальная,
  на репозиторий и сборку не влияет; `legacy-ts/core` НЕ исключён — живая
  зависимость `server/`). Это убрало ~90% строк того отчёта.
- Прогнаны гейты: `flutter analyze` → **No issues found**, `npm test` → **96/96**.

## Осознанные ложные срабатывания (чинить НЕ нужно)

- **Android-манифест / `styles.xml`** (`Cannot resolve android:*`,
  `Attribute ... is not allowed here`) — IDEA без Android-фасета не знает схему.
  Сборка Flutter/Gradle проходит. Это не наш баг.
- **CSS custom properties** (`Cannot resolve '--font-display'` и т.п.) — все были
  в `legacy-ts/ui/styles.css` (теперь исключён); переменные задаются динамически.
- **Опечатки в идентификаторах** (`Riverpod`, `Fredoka`, `Baloo`, `Segoe`,
  `SRCROOT`…) — это имена библиотек/шрифтов/констант, не ошибки.
- **`Missing await` в `server/leaderboard.ts`** — намеренный fire-and-forget
  дебаунс записи (в коде: «не блокируем event-loop»; для shutdown есть `flushNow()`).
  Ждать здесь нельзя — это by design.
- **`Unused method onConnect/onMessage/onRequest`** в `server/*.ts` — это
  колбэки WS-фреймворка, вызываются рантаймом, не мёртвый код.

## Как держать чисто дальше

- Проверяй **живой код** через `flutter analyze` и тесты — это истина, а не список IDE.
- Инспекции IDEA запускай **по области** (Scope), а не по всему репо: замороженные
  папки уже исключены в `.iml`, поэтому «Inspect Code» больше не будет их показывать.
- Если снова увидишь пугающий список — вернись сюда и разложи его на 3 кучки.
  Почти всё окажется 🟥 или 🟨.
